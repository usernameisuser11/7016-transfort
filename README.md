# 상명대 스마트 통학 V5

7016 · 서대문08 · 종로13의 학교행 정류장과 실시간 버스 정보를 **현재 위치 + 보행 경로**와 결합해, 상명대학교 서울캠퍼스까지 가장 현실적인 통학 경로와 출발 시점을 안내하는 PWA입니다.

V5의 기준은 단순한 `가장 가까운 정류장`이 아닙니다.

```text
현재 위치 → 정류장 도보시간
          + 탑승 가능한 버스 대기시간
          + 버스 이동시간
          + 하차 후 학교까지 도보시간
          = 학교까지 총 예상 소요시간
```

정류장 A가 더 가까워도 학교 도착이 정류장 B보다 늦으면 B를 우선 추천합니다.

## V5 핵심 변화

- 카카오맵의 `출발 → 도착 → 경로` 흐름만 참고하고 통학에 필요하지 않은 입력은 제거
- 목적지는 **상명대학교 서울캠퍼스 고정**
- 출발지는 브라우저의 현재 위치로 자동 설정
- 7016 · 서대문08 · 종로13의 실제 학교행 정류장 후보만 비교
- 거리순이 아니라 **학교까지 총 소요시간 순으로 경로 선택**
- 도보시간 + 버스 ETA + 90초 안전여유를 이용해 `언제 출발할지` 계산
- 걸어서 도착하기 어려운 첫 차량은 제외하고 다음 차량 검토
- 현재 위치를 사용할 수 없거나 동의하지 않은 경우 노선/정류장 수동 선택 가능
- 위치 좌표는 서비스 DB에 저장하지 않음
- AI UI와 AI 호출을 제거하고, 핵심 판단을 전부 규칙/실시간 데이터 계산으로 처리
- 월간 승하차 데이터는 `실시간 혼잡도`가 아니라 통계 기반 참고정보로 분리

## 화면 원칙

첫 화면에서 사용자가 확인해야 하는 답은 세 가지입니다.

1. **어느 정류장으로 갈지**
2. **언제 출발해야 할지**
3. **학교에 언제 도착할지**

상세 노선이나 대체 경로는 사용자가 요청할 때만 펼칩니다.

## 위치정보 처리

V5는 위치 기능을 실행하기 전에 서비스 내부의 위치정보 이용 안내를 먼저 보여주고, 동의한 경우에만 브라우저 위치 권한을 요청합니다.

- 현재 위치는 정류장 후보와 보행시간 계산에 사용
- 정확한 위도/경도를 DB에 영구 저장하지 않음
- 보행 경로 API 요청 좌표는 URL query가 아니라 **POST body**로 전송
- 위치 권한을 거부해도 수동 정류장 선택으로 이용 가능

실제 공개 운영 전에는 운영 주체와 제공 방식에 맞는 위치기반서비스 이용약관, 개인정보 처리방침, 신고 의무를 최종 확인해야 합니다.

## 보행 경로

`TMAP_APP_KEY`가 설정되어 있으면 서버의 `/api/walk`가 TMAP 보행자 경로안내 API를 사용해 현재 위치에서 정류장까지의 실제 도보 거리/시간을 계산합니다.

TMAP 키가 없는 개발환경에서는 앱이 중단되지 않고 직선거리 기반 임시 추정값으로 fallback 하며, 화면에 `거리 기반 임시 추정`이라고 표시합니다.

## 실시간 버스

기존 서울시 버스 Open API 연동을 그대로 활용합니다.

- 노선별 학교행 정류장
- 첫 번째/두 번째 도착 차량 ETA
- 차량 위치와 실시간 혼잡 정보(제공되는 경우)
- 선택 정류장에서 상명대정문까지의 예상 이동시간
- 월간 시간대별 승하차 통계

## 추천 계산

각 후보 정류장에 대해 다음을 계산합니다.

```text
탑승 가능 조건
버스 ETA >= 정류장까지 도보시간 + 안전여유시간

총 소요시간
= 버스가 현재 정류장에 도착할 때까지의 시간
+ 해당 차량의 상명대정문까지 이동시간
+ 최종 학교 도보시간
```

현재 기본 안전여유는 90초입니다.

## Render

`render.yaml`에서 필요한 비밀 환경변수는 다음 두 개입니다.

```text
DATA_GO_KR_SERVICE_KEY
TMAP_APP_KEY
```

Render 무료 Web Service를 사용하는 경우 일정 시간 요청이 없으면 첫 접속이 느릴 수 있습니다.

## AI 정책

V5 사용자 흐름에서는 AI를 사용하지 않습니다.

- Gemini 분석 메뉴 제거
- 프론트엔드 AI 호출 제거
- `/api/ai-advice` 비활성화
- 경로 추천과 출발 판단은 위치/보행/실시간 버스 데이터와 명시적인 계산식으로 처리

기존 서버 파일에 남아 있는 AI 관련 레거시 코드는 기존 버전 호환을 위해 당장 제거하지 않았으며, V5 실행 진입점에서는 해당 엔드포인트를 비활성화합니다.
